What is in it

A plant, its safety layers and the agents

A plant you can break

A dynamic process model with 8 PI loops, duty/standby pump trains, ISA-18.2 alarms and 11 independent safety functions. Inject pump trips, valve and sensor faults or disturbances.

Fault detection

PCA (Hotelling T² and SPE) watches every reading and confirms faults; rule checks and an LLM diagnosis agent rank the likely causes.

AI operator agents

A knowledge graph, a planning agent and an action agent propose concrete commands: setpoints, standby pumps, throughput, emergency devices.

Checked before they act

A digital twin, an LLM judge or the ADMIT hard gates validate every proposal; rejections go back to the agent with the reason.

How it works

How a decision is made

  1. MonitoringPCA confirms a fault
  2. Knowledge graphfault → symptoms → actions
  3. Planningtarget and objective
  4. Action agentproposes commands
  5. ADMIT gateT0–T4 checks
  6. Dispatchapplied to the plant

With ADMIT, the action agent files an action record with every command: the evidence it relied on, the procedure steps it followed, its confidence, and whether and how the action can be undone. The platform builds the evidence ledger from the live plant, then ADMIT checks the record gate by gate:

  • T0the record is complete and valid
  • T1the cited evidence exists, is trusted and fresh
  • T2the active hazard is addressed
  • T3authority, operating mode and procedure steps
  • T4the plan, projected on the plant, stays inside the safety limits

Only an admissible plan is applied. Every record, rule and gate result is shown in the console and logged.

Results

20 fault scenarios, six configurations

The same single, coupled and triple faults, the same fault-lift times and economics for every configuration. Agents run with gpt-5-nano; one run per configuration, so differences of 2–3 stops are within the run-to-run noise.

Download

Run it on your own computer, free

Everything runs on your machine: the plant, the console in your browser and the agents. All downloads are on the latest release.

Windows app

Run the installer, then start OperAItor from the Start menu. The console opens in your browser; closing the OperAItor window stops it. No administrator rights needed.

Not code-signed yet: if Windows says “Windows protected your PC”, choose More info → Run anyway.

Download for Windows

Portable zip and pip wheel: releases page.

Docker

Windows, Mac or Linux with Docker Desktop:

docker run -p 7860:7860 \
  ghcr.io/aisl-at-imperial-college-london/operaitor

then open http://localhost:7860.

Python 3.11+

For researchers using the plant or the benchmark in their own code:

pip install "operaitor[llm]"
operaitor serve

then open http://localhost:8001.

Let the agents act

Without an LLM the plant, fault detection and safety functions all work, and the agents monitor and diagnose. To let them act, connect one in Agents → Agent settings:

  • Groq free tier
  • Google Gemini free tier
  • OpenRouter free models
  • Ollama free, local
  • OpenAI your own key

Switch models at any time from the same card.

Your key stays with you

Your browser calls the AI provider directly with your key. The key is held in your browser tab only and is never sent to the OperAItor server.

The Windows app and the Docker image include the ADMIT validator. With pip, add it with pip install "admit-bench @ git+https://github.com/Refiant-Inc/admit-bench.git". From source: see the README.
